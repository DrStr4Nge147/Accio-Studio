Accio Studio, design proposal

Direction: "Lamplight on ink." A near-black ink canvas with a single warm gold light, used only for the thing that matters right now: the primary action, the active state, the progress line. Soft serif for the brand and big moments, a clean grotesque for the interface. The image is always the brightest thing on screen.

Everything below is a static prototype: no real data, no build. Placeholders in gradient stand in for generated images. Toggle the theme at the top right to see the light version of every screen.

Wordmark and icon

Lowercase accio in a high-contrast serif, traced from the approved logo artwork. The final "o" is a rounded-rectangle ring, cut by a slit on the left and opened on the right, with a gold spark above and a cursor below: something being summoned into the frame. The same ring becomes the app icon, the loading spinner and the Generate-complete flash, so one shape carries the whole brand.

Studio

App icon on ink, maskable-safe (ring sits inside the 80% safe zone). The ring is symmetric top to bottom and stays legible down to a 16 px favicon. Monochrome variant (no gold) for the Android themed icon.

Palette

Ink for surfaces, parchment for text, one gold. Gold is never decoration: if it's lit, it's active, primary or progressing. Image content never gets tinted. Semantic green and red appear only for success and errors.

Typography

Used sparingly: brand, empty/first-run states, sheet titles. Never for controls.

Interface, Instrument Sans
Prompts, buttons, labels and settings. Sentence case everywhere, 15 px base, 13 px for chips and captions, 12 px for meta. Weights 400, 500, 600 only.
Numbers and seeds, JetBrains Mono

Fonts are self-hosted (variable WOFF2, Latin subset, about 60 KB total, font-display: swap), so there is no Google Fonts request and the PWA works offline. This preview loads them from Google Fonts for convenience and falls back to Georgia / system sans if offline. Scale: 12 / 13 / 15 / 17 / 22 / 28 / 40.

Shape and elevation: radii 10 / 14 / 22 / pill; three surface levels (surface, raised, overlay) separated by 1 px hairlines, not heavy shadows. Icons are 1.7 px-stroke lucide-style line icons, 20–24 px, with 44 px touch areas.

Navigation model

Mobile: four tabs

  • Create opens on the prompt dock + results feed. Standard / Detailed is a toggle in the dock.
  • Edit opens on a mode strip: Multi-edit · Inpaint · Outpaint. Each one is a different canvas layout.
  • Gallery is all history, full-bleed grid, swipe between images in the viewer.
  • Settings is the fourth tab: connection (QR, tunnel URL, server and backend status), theme, install, password. No gear in the top bar.
  • The dock is a bottom sheet: collapsed = a prompt that grows with its text, up to three chips and Generate; Options (or drag up) opens everything else.

Desktop: three-pane workspace

  • Left (316 px): Create / Edit / Gallery switch, then the composer for the current mode. Generate is pinned at the bottom of the pane.
  • Center: the canvas. Result viewer, Multi-Edit compare slider, mask brush, outpaint handles.
  • Right (272 px): queue on top, history below. Click a thumbnail to load it in the canvas, drag it to a reference slot.
  • Shortcuts: Ctrl+Enter generate, [ ] brush size, Ctrl+Z undo, Space pan, 1/2/3 switch mode.

One composer pattern: prompt, a row of main-toggle chips, Generate. It is the same component docked at the bottom on mobile and in the left pane on desktop. It never covers the image. Everything else (seed, steps, LoRAs, sizes) is in Advanced.

Mobile screens

360 × 740 frames, thumb-first. Primary actions live in the bottom 40% of the screen. All tap targets are at least 44 px (the chips are 36 px tall inside a 44 px hit area, which I'll do with padding in the real build).

Designed states (not afterthoughts)

First run

Empty Create feed: a faint ring outline, "Nothing summoned yet", and the prompt dock already focused with three one-tap example prompts.

Setup check

If a model or node is missing: a list with status per item (found / missing), size, and a "Download missing models" button. Generate stays disabled with the reason.

Errors

ComfyUI offline, validation, execution error: an inline card in the result slot with a plain sentence, a Retry, and "Details" that never shows paths or stack traces. Cancelled jobs show "Cancelled" and keep their settings.

Desktop screens

Motion

The reveal

1.1 s: a gold ring of light opens from the center, the blurred preview resolves into the final image.

Rules

  • CSS transitions and transforms only (150–250 ms, ease-out). No animation library in the first bundle.
  • Animate transform, opacity and clip-path; never layout properties.
  • The reveal plays once per finished image, only for the job on screen, never in lists or the gallery.
  • prefers-reduced-motion: reveal becomes a 250 ms fade, shimmer stops, sheets snap.
  • Progress and preview updates are throttled to 10 per second.
  • Skeletons (soft ink blocks with the shimmer) instead of spinners wherever the layout is known.

For your approval

Decisions this proposal makes, so you can veto any of them:

  • Direction: "Lamplight on ink": ink surfaces, parchment text, one gold accent; light theme is cool starlit mist (blue-grey neutrals, midnight text) with the same gold.
  • Type: Fraunces (brand + moments), Instrument Sans (UI), JetBrains Mono (seeds, numbers), all self-hosted.
  • Wordmark / icon: lowercase "accio" with the final "o" as a rounded open ring, a gold spark above and a cursor below.
  • Navigation: mobile 4 tabs (Create / Edit / Gallery / Settings), a calmer dock with a growing prompt, at most three chips plus Options, Edit sub-modes as a segmented control. Desktop 3 panes with queue + history on the right.
  • Stack additions: none beyond the spec's baseline (React, Vite, Tailwind, lucide-react, Zustand). Design tokens become CSS variables mapped into Tailwind.
  • Aspect presets (spec 6.3, unverified with Krea2) stay as proposed there.
  • Button label stays plainly "Generate"; the summoning feeling lives in the reveal and progress copy ("Summoning…").

Still open from the spec and not a design question: the Remove / Move object preset input format (spec 6.4), which I will ask again before Phase 5.
